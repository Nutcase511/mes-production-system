# src/services/

## 目录用途
API 服务层目录，封装所有与后端 API 交互的逻辑，提供统一的数据访问接口。

## 服务设计原则
- 单一职责（一个服务负责一个业务领域）
- 统一的错误处理
- 类型安全的 API 调用
- 支持请求取消
- 提供清晰的方法文档

## 典型服务结构
```typescript
import { api } from '@/lib/airiot-client'
import type { ApiResult } from '@/types/api'

export const xxxService = {
  // 获取列表
  getList: async (params: any) => {
    const response = await api.get('/xxx/list', { params })
    return response.data
  },

  // 获取详情
  getDetail: async (id: string) => {
    const response = await api.get(`/xxx/${id}`)
    return response.data
  },

  // 创建
  create: async (data: any) => {
    const response = await api.post('/xxx', data)
    return response.data
  },

  // 更新
  update: async (id: string, data: any) => {
    const response = await api.put(`/xxx/${id}`, data)
    return response.data
  },

  // 删除
  delete: async (id: string) => {
    const response = await api.delete(`/xxx/${id}`)
    return response.data
  },
}
```

## 技术要点
- 使用 axios 进行 HTTP 请求
- 统一的请求/响应拦截器
- 自动添加认证 token
- 统一的错误处理
- 支持 TypeScript 类型检查
- 处理 loading 和 error 状态

## 与其他目录的关系
- 被 `pages/` 和 `blocks/` 中的组件使用
- 使用 `lib/` 中的工具函数
- 使用 `types/` 中的类型定义
- 通过 AIRIOT SDK 调用平台 API

## 注意事项
- 服务方法要提供完整的类型定义
- 统一处理 API 错误
- 考虑请求的性能优化
- 提供服务文档和使用示例
- 避免在服务中包含 UI 逻辑
